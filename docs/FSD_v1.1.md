## 0. エグゼクティブサマリー

ICHICOの広告営業職が、プランナーの伴走なしに、クライアント前で即座にCM出稿プランの試算・比較・提案根拠提示までを完結できるSaaS。市場リファレンスはスイッチメディア「TVAL」だが、ICHICOの差別化軸は以下の3点に絞る。

1. **既存Excelロジック資産の継承**: ポアソン分布リーチモデル、業界別CM効果係数、絵柄4分類、エリア×局×ターゲットマスタを全て継承し、初期実装でも実用精度を確保
2. **「曜日・時間区分集計」のオプショナルインポートによる高精度モード**: 営業がビデオリサーチ等から入手したデータを追加すると、絵柄ごとのターゲット実効リーチ係数を自動算出
3. **Google Drive上での階層的プラン管理**: 企業×案件×プランの3層構造で過去提案を即座に呼び出し、社内インフラ依存ゼロで運用

## 3. ロジック設計（核心部・最終確定）

### 3.1 リーチカーブモデル（ポアソン分布モデル）

```
リーチ人数 = エリア視聴人口 × (1 − POISSON.DIST(F−1, k × GRP, TRUE))
```

- **F**: 有効フリークエンシー閾値（デフォルト6）
- **k**: CM効果係数（1GRPあたりの平均接触回数の係数）
- **POISSON.DIST(x, λ, TRUE)**: ポアソン分布の累積分布関数。「接触回数≤x」となる確率

**数学的解釈**: 視聴行動がポアソン分布に従うと仮定すると、平均接触回数 λ=k×GRP のとき、F回以上接触する人の割合は `1 − P(接触<F) = 1 − POISSON.DIST(F−1, k×GRP, TRUE)`。これに視聴人口を乗じることで有効リーチ人数を得る。

**業界標準性**: このモデルは Naples (1979), Krugman (1972) 以来の有効フリークエンシー理論を確率分布で表現したもので、電通STADIA・博報堂DYMP・ニールセン等のメディア分析でも標準的に使われる。

### 3.4 標準モード vs 高精度モード（曜日・時間区分インポート）

**標準モード**（インポートなし）:
```
k_effective = k_industry × creative_pattern_coefficient_default[絵柄]
```
絵柄ごとの補正係数は経験則値（暫定: 全日1.0 / ヨの字1.05 / コの字1.10 / 逆L1.20）。

**高精度モード**（インポートあり）:
```
1. インポートデータから「ターゲット×局×時間帯×曜日」の視聴率マトリクスを取得
2. 絵柄定義に従って該当時間帯のセルを抽出
3. 絵柄ごとに加重平均視聴率を算出
   weighted_rating[ターゲット][絵柄][局] = Σ(rating[t,d]) / N_cells

4. ターゲット×絵柄×局の「実効視聴率係数」を計算
   effective_coefficient = weighted_rating / overall_average_rating

5. ポアソンモデルのkを補正
   k_effective = k_industry × effective_coefficient
```

これにより、同じGRPでも「F1ターゲットに対する逆L枠」と「F3ターゲットに対する全日枠」で異なるリーチ効率が反映される。

### 3.5 放送局選定によるリーチ補正（Sainsbury式）

```
Reach_combined = 1 − ∏(1 − Reach_i × adjustment_i)
```

- adjustment_i: 局選定による視聴重複補正
- 局間相関係数 ρ を考慮: `adjustment_i = √(1−ρ_i)`

実装上は、選択された局の組み合わせから合成リーチを算出。曜日・時間区分インポートがある場合は、局別視聴率の実測値から相関係数を逆算する（高精度モード）。

**GRP按分（実装既定）**: 選択局へ総GRPを配分する。既定は局パーコスト比例のコスト加重（`cost_weighted`）。均等（`equal`）も切替可能。

```
局GRP_i = 総GRP × 配分比率_i
配分比率_i（コスト加重）= パーコスト_i / Σパーコスト
配分比率_i（均等）= 1 / 局数
```

### 3.6 コスト計算（既存ロジック継承）

```
出稿総額 [円] = Σ(局GRP_i × 局パーコスト_i)
リーチ単価 [円/%] = 出稿総額 / リーチ率 [%]
CPM [円/千回] = 出稿総額 / (GRP × 母数(千人) / 100) = 出稿総額 / (GRP × 母数(人) / 100,000)
ターゲット表示単価 [円/回] = 出稿総額 / (GRP × 母数(人) / 100)
出稿本数 [本] = ROUNDDOWN(GRP / 平均視聴率, 0)
```

局パーコストはマスタから取得し、画面上では整数円のみ上書き可能。絵柄別単価はコスト計算で別途乗算。**ICHICO実勢パーコストを優先採用**（萩さん回答: 社内データあり）。

### 3.7 最効率GRP算出（2方式併設）

**方式A: webコストパリティ法（既存Excel採用）**
```
最効率GRP_A = テレビCMのリーチ単価がweb動画CPM（デフォルト2.3円）と等しくなるGRP
```
営業現場では「テレビと動画、どちらが効率的か」の議論に直結し有用。

**方式B: 限界効率法（FSD v1.0で提案）**
```
最効率GRP_B = 限界リーチ効率が初期効率の50%まで低下するGRP
        ≈ ポアソン関数の数値解で k×GRP の閾値を逆算
```

UIで両方併記し、営業が状況に応じて選択可能。

### 3.8 CM残存効果（アドストック）とCM認知率

```
Adstock_t = α × GRP_t × effective_coefficient + λ × Adstock_(t-1)
認知率_t = MaxAwareness × Adstock_t / (Adstock_t + K_awareness)
```

- α: 即時効果係数（デフォルト0.3）
- λ_w: 週次残存係数（内部基準。商材プリセットで可変）
- MaxAwareness: 最大到達認知率（デフォルト30%、商材により可変）
- K_awareness: 認知率半飽和点（デフォルト50、要キャリブレーション）

期間粒度（週/月）と残存換算:
```
λ_m = λ_w ^ 4.345
Adstock の当期投入は期間内減衰を periodImpactFactor で補正
```

プラン入力の GRP はキャンペーン合計。期間別GRP（手入力またはプリセット配分）をアドストック系列へ渡す。

### 5.3 同期戦略

- 起動時: Driveの `_index.json` を読込、IndexedDBにキャッシュ
- 編集中: ローカル（IndexedDB）にリアルタイム保存
- 保存時: Driveにアップロード、`_index.json` 更新
- オフライン: ローカルのみで動作、復帰時に自動同期
- コンフリクト: last-write-wins、ただし保存前に「他デバイスで更新されています」警告

### 5.4 営業向け運用ガイド

- 初回認証: 営業がGoogle認証画面で権限付与（1回のみ）
- ストレージ消費: プラン1件あたり約5-20KB、影響は無視できる
- 共有: Drive側で `ICHICO_TV_Planner` フォルダを共有することでチーム展開可能

### 6.5 「精度ラベル」常時表示

各KPIに以下のいずれかのラベルを表示。

- **[標準精度]**: 業界経験則のみで算出。誤差±20-30%目安
- **[高精度]**: 曜日・時間区分実測データに基づく。誤差±10-15%目安
- **[実勢値]**: ICHICOの過去実出稿データで検証済み。誤差±5-10%目安

これにより営業はクライアントに「この数字は実測ベースです」「これは目安です」と区別して伝えられる。

## 9. キャリブレーションと精度運用

### 9.1 段階的キャリブレーション計画

| Phase | 対象 | データソース | 精度 |
|---|---|---|---|
| 初期実装 | 業界係数・パーコスト・人口 | 既存Excel | 標準精度 |
| Phase 1 | 宮城パーコスト実勢値 | ICHICO社内実勢データ | 実勢精度（宮城） |
| Phase 2 | 曜日・時間区分実測 | 営業ユーザーがインポート | 高精度（インポート時） |
| Phase 3 | 局間相関係数 | 過去実出稿データ | 高精度 |
| Phase 4 | アドストック・認知変換 | MMM分析 | 高精度 |

### 9.2 不確実性の明示

すべての出力に「シミュレーション値です。実出稿結果との誤差は±◯%程度を想定」と注記。営業がクライアントに過信を与えないため。

## 10. リスクと留意事項

| リスク | 影響 | 対策 |
|---|---|---|
| 絵柄時間帯定義の経験則依存 | 高精度モードの精度が業界実態とズレる可能性 | 設定ファイルで時間帯定義をICHICO営業ヒアリングで補正可能に |
| 局名表記揺れ | インポート時にマッピング失敗 | マッピングテーブルを設定UIで編集可能に |
| Google Drive APIレート制限 | 大量保存時に同期失敗 | バッチ書き込み・エクスポネンシャルバックオフ実装 |
| OAuth未承認警告 | 営業の初回利用時の心理障壁 | 社内マニュアル整備、本格展開前にGoogle審査取得 |
| 認知率モデルのカテゴリ依存 | 商材により精度低下 | 認知度3段階プリセットで補正、係数編集可能 |
